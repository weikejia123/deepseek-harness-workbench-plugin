## 需求要点

文件树标签页现有「文件 / GIT / 用量」，新增第 4 个图标标签「归档」：
- 显示 dsh **所有归档会话** + **归档时间**
- 点击某归档会话可**切换**到该会话查看（用户不继续会话，目的是看记录、复制信息）

## 关键调研结论（dsh 平台事实）

1. **归档集合**：`archivedSessionIds: SessionId[]` 存于 workspace 域状态（`dsh-workspace/src/spec.ts` `archivedSessionIds`），client 侧通过 `useWorkspaces(state => state.archivedSessionIds)` 可读。
2. **官方 UI 隐藏归档**：`dsh-client-ui-workspace/src/client/tree.ts` `sessionVisible()` —— 归档会话"visible nowhere"；官方侧边栏不提供任何归档列表。
3. **无归档时间戳**：`archiveSession()` 只把 id append 进 `archivedSessionIds`，**dsh 不持久化归档时间**。会话的最后活动时间在 `SessionSummary.updatedAt`。
4. **打开归档会话 = 运行时硬拦截**（V3 真机验证结论）：
   - `dsh-client-runtime/src/client/workspaces/service.ts` `project()`（L342-344）：`if (sessions.current !== undefined && workspace.archivedSessionIds.includes(sessions.current)) this.sessions.clear()` —— 任何把归档会话设为 current 的选择会被立即清除，布局回落 New Session 空态。源码注释："a hidden row must not stay open behind the list"。
   - **无 unarchive API**：host 契约 `apiproxy/src/api/workspace.ts` 注释 "a future unarchive restores its position"；`workspaceRegistry` 只有 `archiveSession()`，无 unarchive 方法。归档单向。
5. **只读读取可行**：host `sessions.history` RPC（`{ sessionId, beforeSeq?, maxMessages? }`）**无归档过滤**（`historySourceFor()` 走 attached Session 或持久化日志 `inspectServable`，不 resume Agent）；client 侧 `ctx.connection.api` 可调用。

## 结论与教训

- **通用插件无法在官方会话视图打开归档会话**：dsh 运行时对归档选中做了硬清除，且无 unarchive API —— 这是平台级限制，不是插件实现问题。
- 只读转录（`sessions.history`）在技术上是可行的，但真机评估点击无内容、价值低，按用户决定**整体删除**，避免遗留无用能力污染插件。
- 若未来 dsh 提供 unarchive 或官方归档查看能力，再按需评估是否恢复。
