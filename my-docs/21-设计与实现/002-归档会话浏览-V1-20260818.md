## 需求要点

文件树标签页现有「文件 / GIT / 用量」，新增第 4 个图标标签「归档」：
- 显示 dsh **所有归档会话** + **归档时间**
- 点击某归档会话可**切换**到该会话查看（用户不继续会话，目的是看记录、复制信息）

## 关键调研结论（dsh 平台事实）

1. **归档集合**：`archivedSessionIds: SessionId[]` 存于 workspace 域状态（`dsh-workspace/src/spec.ts` `archivedSessionIds`），client 侧通过 `useWorkspaces(state => state.archivedSessionIds)` 可读。
2. **官方 UI 隐藏归档**：`dsh-client-ui-workspace/src/client/tree.ts` `sessionVisible()` —— 归档会话"visible nowhere"；官方侧边栏不提供任何归档列表。
3. **无归档时间戳**：`archiveSession()` 只把 id append 进 `archivedSessionIds`，**dsh 不持久化归档时间**。会话的最后活动时间在 `SessionSummary.updatedAt`（client `useSessions(state => state.byId)`）。
4. **打开会话**：client `sessions.open(id)`（`ISessions.open`，id 须在列表中存在；归档会话仍在 list store 中，只是 UI 过滤掉）。

## 设计决策（Why）

### D1. 数据全部走 client 侧现有 store，零 host 改动

`useWorkspaces(archivedSessionIds)` + `useSessions(byId)` 已覆盖全部所需数据（id 集合、标题、更新时间），**不需要扩展 host `/git` API**，风险最小、与现有架构（浏览器侧只读 store）一致。

### D2. 归档时间的诚实处理

dsh 无归档时间字段。方案：**插件自维护归档时间表**（localStorage `dsh-workbench-archive-times`）：
- `WorkbenchInner`（常挂载）订阅 `archivedSessionIds`，检测到**新出现**的 id 时记录 `Date.now()`；
- 展示时优先插件记录的归档时间，**无记录时回退 `updatedAt`**（界面文案标注为「最后活动」），保证老归档会话也有可用时间且不撒谎。
- 归档时间表是渐进式增强：插件启用前已归档的会话无真实时间，回退显示最后活动时间。

### D3. 打开归档会话

- 通过 `ctx.sessions.open(id)`：`client/index.ts` 的 `apply(ctx)` 把 `openSession` 注入 `WorkbenchInjected` → `SideDock` → `ArchivesPanel`。
- 已知风险（真机验证项）：归档会话被官方 UI 隐藏，打开后 conversation 区域应能加载消息记录（projection 数据独立于侧边栏可见性）；若官方对归档会话的加载有额外限制，退路是改用 host `sessionQuery.readSession` 走只读渲染（本版先走 open，标注验证）。

### D4. 排序与展示

- 按显示时间（归档时间或最后活动）**倒序**，最新在前。
- 行内容：会话标题（`displayTitle`，官方语义）+ 时间（本地化 `YYYY-MM-DD HH:mm`）；当前会话高亮。
- 空态提示 + 归档计数。
