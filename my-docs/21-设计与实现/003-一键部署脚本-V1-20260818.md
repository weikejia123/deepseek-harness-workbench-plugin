# 003 一键部署脚本 — 设计实现报告

> 功能大类：本地部署工具（my-scripts/deploy.sh）
> 文档版本：V1-20260818

## 元信息

| 项 | 值 |
|----|----|
| 插件 | deepseek-harness-workbench-plugin（wkj-dev） |
| 需求来源 | 二开配套：官方 devops/*.sh 依赖 mise，本机未安装 mise（`setup.sh` 直接报「未找到 mise」），二开需频繁部署，要求一键脚本且自动安装依赖 |

## 需求要点

1. 在插件目录 `my-scripts/` 编写一键部署 sh 脚本。
2. **不依赖 mise**（本机无 mise，用 PATH / nvm 的 node + pnpm）。
3. **自动安装依赖**（node_modules 缺失或依赖变更时自动 `pnpm install`，免跑官方 setup.sh）。
4. 一条命令完成：装依赖 → 构建 → 安装到 web profile。

## 设计决策（Why）

### D1. 工具链检测：PATH 优先，nvm 兜底

- `ensure_node`：`command -v node` 优先；缺失时取 `~/.nvm/versions/node/*` 最新版本加入 PATH（本机实测 nvm node v24.19.0 满足 engines `^22.19 || >=24`）。
- `find_pnpm`：PATH 优先，其次 nvm 对应目录；都无则报错并给出安装提示。

### D2. 复用官方部署语义，但不耦合官方脚本

- 保留官方 dev.sh 的**旧包名清理**（dsh-git-plugin 残留 → remove + rm，防双加载）。
- `dsh plugin --profile web add "$ROOT"` 安装**本地仓库**（link 到 web profile，改源码后重新跑脚本即更新）。
- dsh CLI 定位：PATH 的 `dsh` → `~/.dsh/profiles/node_modules/.bin/dsh` → `@deepseek-ai/dsh/lib/bin.js`（node 前缀）→ 本地 harness 软链；`read -r -a` 拆分为数组执行，兼容「node /path/bin.js」这类多 token 命令。

### D3. 启动策略：默认不重启，`start` 参数可选

- 默认只部署不启动（避免误中断正在运行的 dsh web）；`start` 参数追加 `devops/start-web.sh`（停 3080 再前台启动）。

### D4. bash 3.2 兼容性（实现中踩坑）

- macOS 默认 bash 3.2 对「命令替换内嵌套引号 `$("$VAR" -v)`」以及「全角括号包裹裸变量 `（$VAR）`」的解析有 bug（变量名被截断报 unbound）。
- 规避：嵌套命令替换先存入中间变量；变量一律 `（${VAR}）` 花括号形式。

## 实现要点

| 文件 | 说明 |
|------|------|
| `my-scripts/deploy.sh` | 一键部署：工具链检测（node/pnpm）→ pnpm install → pnpm build → 定位 dsh → 清理旧包名 → plugin add 本地仓库 → （可选）启动 |
| 用法 | `bash my-scripts/deploy.sh`（部署）/ `bash my-scripts/deploy.sh start`（部署并启动）/ `--help` |

## 验证方式

- ✅ 本机实测完整跑通：工具链检测 → pnpm install → build → plugin add 成功；
- ✅ `~/.dsh/profiles/web/package.json` 中 `dsh-workbench-plugin` 变为 `link:<本仓库>`，node_modules 软链指向本地仓库；
- ✅ `--help`、语法检查通过；重启 dsh web 后二开生效（未代执行启动，避免中断当前会话）。
